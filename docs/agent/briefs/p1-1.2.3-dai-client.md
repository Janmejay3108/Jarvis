## 4. File specification

### `src/integrations/dai_client.py`

Harden the existing module; do not replace its public surface or couple it to pipeline/model code.

#### Public models and API

Keep this public model exactly:

```python
class LogEntry(BaseModel):
    model_config = ConfigDict(coerce_numbers_to_str=True, extra="ignore")

    id: str | None = None
    eventtime: str | None = None
    testrunid: str | None = None
    message: str | None = None
    severity: str | None = None
    step_id: str | None = None
    stage: str | None = None
    message_type: str | None = None
    image_name: str | None = None
    image_id: str | None = None
```

Fields are optional because production entries are heterogeneous and nullable. Numeric IDs are coerced to strings. Unknown production metadata is ignored, not persisted into the model. Do not rename `eventtime` to the JARVIS-DAI log field `timestamp`.

Keep these `DaiClient` signatures:

```python
def __init__(
    self,
    config: Settings | None = None,
    client: httpx.AsyncClient | None = None,
) -> None
async def aclose(self) -> None
async def __aenter__(self) -> Self
async def __aexit__(self, *_args: object) -> None
async def authenticate(self) -> str
async def log_by_runid(self, runid: str) -> list[LogEntry]
async def fetch_screenshot(self, image_id: str, dest: Path) -> Path
def walk_back_to_screenshot(
    self,
    logs: list[LogEntry],
    error_index: int,
) -> LogEntry | None
def result_url(self, runid: str) -> str
```

Private pydantic models/helpers are encouraged for auth and envelope validation, but do not add a public envelope return type: callers consume `list[LogEntry]`.

#### Instance and configuration separation

- Read only `settings.dai_base_url`, `dai_auth_url`, `dai_client_id`, `dai_client_secret`, `dai_log_by_runid_url`, and `dai_screenshot_url`.
- Never read a `jarvis_dai_*` setting, import `jarvis_dai`, or accept a shared token/cache object.
- The production `httpx.AsyncClient`, auth lock, token, and expiry are instance-owned. An injected client remains owned by the caller; a client created by `DaiClient` is closed by `aclose()` / the async context manager.
- An owned client keeps the existing 120-second request timeout. Remove `verify=False` and use httpx certificate verification defaults. The proven production endpoint is HTTP, so this does not alter that live route; it prevents this client from silently disabling TLS if configuration later uses HTTPS.
- Keep endpoint hosts and paths configuration-driven. Do not hardcode either DAI host, an auth realm, a model ID, or credentials.

#### Authentication and token lifetime

- `POST` exactly to `dai_auth_url` with form-encoded fields `grant_type=client_credentials`, `client_id`, and `client_secret`. Send `Content-Type: application/x-www-form-urlencoded`.
- Parse a non-empty string `access_token` and a finite, positive numeric `expires_in`. Do not retain the current invented `600`-second fallback when `expires_in` is missing. A malformed auth response raises a redacted `ValueError`/pydantic validation error and is never cached.
- Use `time.monotonic()`, never wall-clock time. Cache only in this `DaiClient` instance until `issued_monotonic + max(0, expires_in - 30.0)`. The 30-second safety window is deliberate. A lifetime of 30 seconds or less is immediately considered stale and causes fresh auth on the next use.
- Keep the double-checked `asyncio.Lock`: concurrent callers sharing this production client must cause one auth request, not one per caller.
- Do not decode the JWT, persist it, log it, expose it in errors, or implement refresh-token behavior. On expiry, obtain another client-credentials token.

#### HTTP and retry rules

- Auth, log, and screenshot operations are idempotent reads/token acquisition. Retry each request at most **3 total attempts** on `httpx.TimeoutException` and HTTP **5xx** only, using the existing bounded exponential wait (`multiplier=0.25`, `min=0.25`, `max=2`).
- Do not retry 4xx, JSON/model validation failures, invalid caller arguments, or filesystem failures. Do not add a blanket exception retry.
- Call `raise_for_status()` before parsing or writing. Send `Authorization: Bearer <token>` on evidence GETs. Send `Accept: application/json` for logs and `Accept: image/png` for screenshots.
- Error text and structured logs must not contain the bearer token, client secret, form body, or an authenticated URL. Do not put credentials in URL query/user-info.

#### Run-log behavior

- Reject an empty/whitespace-only `runid` before any HTTP/auth request.
- Format the configured `dai_log_by_runid_url` with the supplied run ID; fail clearly before a request if the template lacks `{runid}`. Percent-encode the value as one path component rather than interpolating raw path/query syntax.
- Accept exactly the two proven top-level forms:
  - a bare JSON list of log-entry objects;
  - a JSON object whose `items` member is a list of log-entry objects. `total_count` and `date_as_of`, when present, may be validated but are not part of the return value.
- Reject any other top-level shape, missing/non-list `items`, or non-object item. Let malformed JSON and pydantic field errors fail loudly. Preserve server ordering exactly and return `list[LogEntry]`.
- Do not filter by severity, select an error, or make an LLM call. Production failures can be `INFORMATIONAL` / `imagefound`.

#### Screenshot behavior and filesystem safety

- Reject an empty/whitespace-only `image_id` and a destination with no filename before auth/network I/O. Require `{image_id}` in `dai_screenshot_url` and percent-encode the ID as one path component.
- Never derive a filesystem path or filename from `image_id`; `dest` is the caller-selected path.
- Require a non-empty response with the PNG signature `b"\x89PNG\r\n\x1a\n"` before touching `dest`. This prevents an HTML/JSON error body from being saved as evidence even when a proxy returns 2xx.
- Create only `dest.parent`. Write to a uniquely named temporary sibling, flush/close it, then atomically replace `dest` with `os.replace`. On download, validation, or write failure, remove the temporary file and leave any pre-existing `dest` unchanged. Return the exact `dest` supplied by the caller.
- Do not introduce a global artifact-root setting in this transport client. Confinement to `data/agent_runs/{run_id}/` remains the pipeline/packager caller's responsibility; atomicity and not using remote IDs as paths are this client's responsibility.

#### Walk-back and result link

- `walk_back_to_screenshot` is deterministic and starts at `error_index - 1`; the error row itself is excluded because Eggplant captures before acting. Return the nearest earlier entry with a non-empty `image_id`, else `None`.
- Treat `error_index` as an index into `logs`: reject negative or out-of-range values with `IndexError` rather than silently clamping to unrelated evidence. Index `0` validly returns `None`.
- `result_url(runid)` performs no network call. Apply the same non-empty/template/encoding rules and return the configured production run-log URL. It must never contain credentials. Do not fall back to or mention the JARVIS DAI.

## 5. Tests to implement

Enumerate these as distinct tests or tightly scoped parameterized tests. Test names may follow repository style, but each assertion is required.

1. **Auth request shape:** form encoding, exact grant fields, production auth URL, no credentials in URL, and returned access token.
2. **Cache before expiry:** two calls before the skewed monotonic expiry make one auth request.
3. **Refresh at expiry:** advancing monotonic time to the cached expiry causes a second auth request and returns the new token.
4. **Concurrent cache fill:** concurrent `authenticate()` calls make one auth request via the lock.
5. **Auth validation:** missing/empty token and missing, non-numeric, non-finite, zero, or negative `expires_in` fail without caching secrets or inventing a lifetime.
6. **Log envelope:** object-with-`items` parses all ten fields, preserves order, and coerces numeric `id`/`testrunid` to strings.
7. **Bare-list compatibility:** the proven bare-list response parses identically.
8. **Malformed logs:** invalid top-level JSON shape, missing/non-list `items`, and a non-object item fail explicitly.
9. **Run ID safety:** empty IDs and a missing URL placeholder fail before requests; reserved characters are encoded as one path component.
10. **Retries:** timeout and 5xx can succeed on the third attempt; a 4xx and malformed JSON get one attempt only. Cover the common request path without duplicating every endpoint combination.
11. **Screenshot success:** bearer/Accept headers are sent, valid PNG bytes are atomically written to a nested destination, and the exact `Path` is returned.
12. **Screenshot rejection:** empty body and non-PNG 2xx body do not create a destination; when the destination already exists, it remains byte-for-byte unchanged and no temporary sibling remains.
13. **Screenshot ID/path safety:** empty ID and missing template fail before requests; encoded ID affects only the request URL, never the caller's destination filename.
14. **Walk-back:** nearest prior screenshot wins; the error row is excluded; index 0/no prior screenshot returns `None`; negative and out-of-range indexes raise `IndexError`.
15. **Result URL:** returns the encoded configured production run-log URL without a request or credentials; empty ID/missing placeholder fails.
16. **Client lifecycle:** owned client closes; injected client remains open.
17. **DAI separation regression:** configure valid production `dai_*` values and deliberately different sentinel `jarvis_dai_*` values; auth/log/screenshot requests must use only production URLs, and no JARVIS token endpoint is called.

Do not add a test that reaches either live DAI. Do not weaken malformed-response assertions to make a fixture pass.
