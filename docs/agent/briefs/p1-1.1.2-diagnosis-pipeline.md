Authoritative specification:

> ### Step 1.1.2 — Diagnosis pipeline (`src/orchestrator/pipeline.py`)
> Async state machine (not a UI generator — it talks to the EventBus; SSE reads the bus):
> `read_ticket (+ runid) → fetch_logs → localize → analyze → post_diagnosis → completed`
>
> `read_ticket`: fetch the Jira ticket, frame ticket evidence, and use an LLM structured extractor for `{runid, title, description, test_script_name}` unless chat supplied an explicit `runid`. Missing runid ends gracefully as `failed (missing_runid)` and tells the user how to retry; never guess.
>
> `fetch_logs`: read the production DAI log, use LLM reasoning to select the one ticket-relevant error entry without severity filtering, deterministically walk backward to the prior screenshot, and download it under `data/agent_runs/{run_id}/`. Frame logs before any LLM call.
>
> `localize`: prefer the failing script/suite named in the DAI log, then use the ticket-number fallback; read local source, build call chain, and compute blast radius.
>
> `analyze`: call `DiagnosisEngine.diagnose(run)`, accumulate tokens/cost, and fail gracefully when `BudgetGuard` trips.
>
> `post_diagnosis`: post the formatted diagnosis and add `ai-diagnosed` only when `settings.jira_writes_enabled`.
>
> Every transition publishes short `agent.message` narration plus artifact events. Any uncaught failure publishes `run.failed`; never crash silently.
>
> **DoD:** mocked end-to-end unit test asserts step order, emitted event sequence, and persisted run row.

#### State machine behavior

Execute these stages exactly:

1. `read_ticket` / `RunStatus.reading_ticket`
   - Begin detail/message: `Reading Jira ticket <ticket_key>`.
   - Call `jira.get_ticket(run.ticket_key)` and retain the full response in `run.ticket_data`.
    - Serialize the entire response with structured JSON (`ensure_ascii=True`, `default=str`), then call `frame_evidence_text(..., label="TICKET")` before extraction.
    - Without an override, call `ticket_extractor.extract(framed_ticket)` once.
   - With `runid_override`, do not call the extractor. Construct metadata deterministically from `ticket["fields"]["summary"]` and `ticket["fields"]["description"]`, defaulting missing/non-string values to `""`; set `test_script_name=""` and `runid=runid_override`.
   - Strip surrounding whitespace from runid. Empty remains missing; never infer or guess another run.
   - Store normalized metadata under `run.ticket_data["jarvis_metadata"]` without deleting the original Jira fields.

2. Missing-runid terminal branch
    - Raise `MissingRunId` from the `read_ticket` stage. The shared stage helper ends it with `await run.end(error="missing_runid")`, omitting `detail` so Decision 001 preserves `Reading Jira ticket ...` in the model, database, and `step.failed` event.
    - The outer `MissingRunId` handler performs only the terminal actions below; it must not end the step a second time.
   - Publish one `agent.message`: `No DAI run ID was found. Re-run with runid=NNN.`
   - Persist the failed run, tokens/cost, completion time, and summary.
   - Publish `run.failed` with the terminal payload and reason `missing_runid`.
   - Return the failed run. Do not call DAI, matcher, localizer, diagnoser, formatter, or Jira writes.

3. `fetch_logs` / `RunStatus.fetching_logs`
   - Begin detail/message: `Fetching production DAI evidence for run <runid>`.
   - Call `evidence.log_by_runid(runid)`. An empty list is an error; do not manufacture evidence.
   - Save JSON-mode log dictionaries to `run.logs`.
   - Build the matcher view with every entry, in order: `[{"i", "message_type", "severity", "message"}, ...]`. Do not filter by severity or message type.
    - Serialize that compact view and frame it with label `DAI_LOG`; call `error_matcher.match` once with framed logs, title, and description.
   - Reject a returned index outside the real log bounds.
   - Call `walk_back_to_screenshot(logs, match.index)`. If it returns an entry with `image_id`, fetch it to `<artifact_root>/<run_id>/failure.png` and append the returned path string to `run.screenshots`. If no prior screenshot exists, continue with logs only.

4. `localize` / `RunStatus.localizing`
   - Begin detail/message: `Localizing the failing SenseTalk path`.
   - Call the injected localizer with the run, metadata, and matched log.
   - Copy its `scripts`, `call_chain`, and `blast_radius` into the run. Do not implement `_locate_test`, call-graph traversal, Bitbucket fallback, or ripgrep here; Steps 1.3.1–1.3.2 own them.

5. `analyze` / `RunStatus.analyzing`
   - Begin detail/message: `Analyzing the failure evidence`.
   - Call `diagnoser.diagnose(run)` once.
   - Set `run.diagnosis`, add outcome token counts and cost to the existing run totals, and persist totals before publishing subsequent events.
   - Publish `artifact` kind `diagnosis` with the diagnosis dictionary after the stage completes.

6. `post_diagnosis` / `RunStatus.updating_jira`
   - Begin detail/message: `Publishing the diagnosis result`.
   - When `jira_writes_enabled` is true, call the formatter once, then `jira.post_comment`, then `jira.add_label(run.ticket_key, "ai-diagnosed")` in that order.
   - When false, call none of those three and end with replacement detail `Jira writes disabled`.
   - Do not add attachments or transitions in this step.

7. Successful terminal branch
   - Set `run.status=RunStatus.completed` and one aware UTC `completed_at`.
   - Persist status, completion time, tokens, cost, and summary JSON.
   - Publish `run.completed` with reason `diagnosed` and current cost.
   - Return the completed run.

#### Failure behavior

Wrap the state machine once at its outer boundary.

- `BudgetExceeded`: fail the active step with safe code `budget_exceeded`, publish `agent.message` text `Run stopped because its model budget was exhausted.`, persist terminal state/totals/summary, publish `run.failed` reason `budget_exceeded`, and return the run.
- Any other exception: fail the active step with the exception class name only, publish `agent.message` text `The diagnosis pipeline failed. Earlier artifacts were preserved.`, persist terminal state/totals/summary, publish `run.failed` reason `pipeline_error`, and return the run.
- Never include `str(exception)`, request headers, response bodies, URLs, tokens, credentials, or tracebacks in user-visible/persisted event payloads.
- If failure occurs between stages, set/persist terminal failed state without fabricating a `step.failed` for an already completed stage.
- Do not catch cancellation as an ordinary failure; re-raise `asyncio.CancelledError`. Step 1.5 owns cancellation UX.

## Review Correction: Evidence Reliability And Framing

Decision 002 supersedes this brief's original use of `untrusted`. Jira and production DAI are authenticated, reliable-provenance evidence sources. Their content is semantically fallible: descriptions can be approximate, comments can be stale, logs can contain many irrelevant failures, and screenshots require interpretation. Jay estimates ticket/log content is often 70–80% accurate; this is an operating estimate supplied on 2026-08-03, not a measured Gate metric and must not be encoded as a threshold.

Reliable provenance does not grant instruction authority. Ticket descriptions, comments, log messages, attachment names, and screenshot text are evidence for diagnosis; text inside them never overrides system instructions or directs tool execution. Corroboration and framing therefore remain required, but the architecture calls this **evidence framing and instruction separation**, not distrust of the source.

The review also proved two defects in the first framing implementation: HTML-escaped text could forge an end marker after entity decoding, and unknown angle-bracket evidence such as `<Suite>` was deleted. Fix both before merge.

## Review Closure Correction: Comment And CDATA Evidence

The independent review of corrective commit `afadea55b171d626c9dc480c6f7f3d6f8ad6ff13`
found one remaining evidence-loss path. `html.parser.HTMLParser` dispatches HTML comments to
`handle_comment()` and CDATA marked sections to `unknown_decl()`; because `_EvidenceExtractor`
implements neither callback, both bodies are silently discarded. DAI messages are serialized and
then passed through this extractor, so XML/log payload inside CDATA can disappear before matching.
This conflicts with the requirement above to preserve domain-specific evidence.

Stay on `build/p1-1.1.2-diagnosis-pipeline`. Preserve the branch as the original implementation
commit plus one corrective commit: amend `afadea5` rather than creating a third commit. The amended
commit hash must change and requires a fresh independent review.

    `parts` without the `<!--` / `-->` wrapper.
