## Local Design Ruling

Step 1.1.1 requires the model's formatted `run_id` and timestamps to be the values persisted in SQLite. The B.6 `StateStore` currently generates an unrelated UUID and its own timestamps. Therefore this brief authorizes a minimal, backward-compatible extension to `StateStore`; it does not authorize a second persistence path or a schema change.

Runtime collaborators must not become serialized Pydantic data. `StateStore` and `EventBus` are attached as Pydantic private attributes by the async factory described below. This keeps `AgentRun.model_dump()` suitable for later artifacts and summaries.

#### Runtime collaborators and factory

Use Pydantic `PrivateAttr` for:

- `_state_store: StateStore | None = None`
- `_event_bus: EventBus | None = None`
- `_active_step: RunStep | None = None`
- `_active_step_id: str | None = None`

Add this factory:

```python
@classmethod
async def create(
    cls,
    state_store: StateStore,
    event_bus: EventBus,
    *,
    ticket_key: str,
    mode: RunMode,
    track_id: str = "enovia",
    conversation_id: str | None = None,
) -> Self:
    ...
```

It must:

1. Construct the model, letting its factories assign `run_id` and `created_at`.
2. Persist the run with the same `run_id`, `created_at`, initial `queued` status, and model metadata.
3. Attach the supplied store and bus to the private attributes.
4. Return the bound model.
5. Not publish `run.queued`; queue ownership and that event belong to Step 1.1.3.

Do not provide an unpersisted fallback inside `begin()` or `end()`. A directly constructed, unbound `AgentRun` must raise a clear `RuntimeError` if either helper is called.

#### Lifecycle helpers

Implement these async methods:

```python
async def begin(
    self,
    name: str,
    status: RunStatus,
    detail: str = "",
) -> RunStep:
    ...

async def end(
    self,
   detail: str | None = None,
    error: str = "",
) -> RunStep:
    ...
```

`begin()` must:

1. Require bound runtime collaborators.
2. Reject a second begin while a step is active.
3. Create one aware-UTC timestamp and use it for both model and persistence.
4. Set `AgentRun.status` to the supplied lifecycle status.
5. Append a `RunStep(status="started")` to `steps` and retain its persisted step ID privately.
6. Persist the run status and append the step through `StateStore`.
7. Publish `step.started` through the existing `EventBus`, with `cost_usd_so_far=self.cost_usd`.
8. Return the `RunStep`.

`end()` must:

1. Require bound runtime collaborators and an active step.
2. Create one aware-UTC completion timestamp and use it for model and persistence.
3. Preserve the active step's existing detail when `detail` is `None`. Replace it when a string is supplied, including an explicitly supplied empty string.
4. If `error` is empty, set the step status to `completed` and publish `step.completed`.
5. If `error` is non-empty, set the step status to `failed`, retain the error, set the run status to `RunStatus.failed`, set `AgentRun.completed_at`, and persist both failed run status and completion time.
6. Complete the persisted step with the same status, timestamp, detail semantics, and error. Pass `None` through to `StateStore.complete_step` when no replacement detail was supplied.
7. Publish through the existing `EventBus`, with `cost_usd_so_far=self.cost_usd`.
8. Clear the active-step private attributes only after persistence and publication succeed.
9. Return the completed or failed `RunStep`.

For all three step events, payload is the JSON-mode dump of the complete `RunStep` and therefore has exactly these keys:

```text
name, status, started_at, completed_at, detail, error
```

Datetime values in event payloads must be ISO-8601 strings. Do not duplicate envelope keys (`event_id`, `run_id`, `ts`, `type`, `cost_usd_so_far`) inside `payload`.
