## 2. Current Anthropic contract and drift ruling

Research was checked against Anthropic's primary documentation and the installed SDK on **2026-08-04**:

- Python SDK: `anthropic 0.120.2`; `AsyncAnthropic` and `client.messages.create(...)` are the current non-beta APIs. Prompt caching no longer uses `client.beta.prompt_caching`.
- Prompt caching: explicit `cache_control: {"type": "ephemeral"}` breakpoints are valid on system text blocks. Usage reports `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, and `cache_read_input_tokens`; `input_tokens` excludes cache-read and cache-write tokens.
- Claude Opus 4.7 prompt-cache minimum: 2,048 tokens. A shorter marked prefix is processed normally and reports zero cache tokens; that is not a client error.
- Opus 4.7 prices: uncached input **$5/MTok**, 5-minute cache write **$6.25/MTok**, cache read/hit **$0.50/MTok**, output **$25/MTok**.
- **Material drift:** Opus 4.7 rejects legacy manual extended thinking (`{"type":"enabled","budget_tokens":...}`) with HTTP 400. For this configured model, `thinking=True` means **adaptive thinking**: `thinking={"type":"adaptive"}` plus `output_config={"effort":"high"}`. Adaptive thinking supports forced tool choice; legacy manual thinking did not.
- Forced tool use remains `tool_choice={"type":"tool","name":"..."}`. The selected output is the matching `tool_use` content block's `input`, not an assumed content index.
- The SDK retries connection failures, 429, and 5xx twice by default. This step owns retry through tenacity, so construct the SDK with `max_retries=0` to prevent multiplicative nested retries.

Primary references:

- <https://platform.claude.com/docs/en/build-with-claude/prompt-caching>
- <https://platform.claude.com/docs/en/agents-and-tools/tool-use/implement-tool-use>
- <https://platform.claude.com/docs/en/build-with-claude/extended-thinking>

- <https://github.com/anthropics/anthropic-sdk-python>

This is an API-drift correction, not a model-policy change. The configured and Keysight-whitelisted reasoning model remains `settings.model == "claude-opus-4-7"`.

## 5. `src/utils/budget.py`

Replace the placeholder-only module while preserving the existing public exception name:

```python
class BudgetExceeded(RuntimeError): ...

class BudgetGuard:
    def __init__(self, limit: float) -> None: ...

    @property
    def limit(self) -> float: ...

    @property
    def spent(self) -> float: ...

    @property
    def remaining(self) -> float: ...

    def charge(self, cost: float) -> float: ...
```

Required semantics:

1. Reject negative, NaN, or infinite `limit` and `cost` with `ValueError`.
2. Keep internal arithmetic in `Decimal` created from string values. Public properties and `charge` return floats for the existing event/storage contract.
3. `charge` records the incurred cost first and returns the new cumulative spend when it remains `<= limit`.
4. When the new cumulative spend is `> limit`, retain the full incurred spend and raise `BudgetExceeded`. The exception message may contain only the numeric limit and spend, never prompt or request data.
5. Exact equality with the cap is allowed; only a strict overage raises.
6. `remaining` never returns a negative number after an overage; clamp it to `0.0`.

The guard is **per run**. `ClaudeClient` accepts one guard and all physical Anthropic responses through that client charge it. Do not create a process-global guard.

### Forced-tool structured output and one repair

`output_model` is required when and only when `tool_choice.type == "tool"`. This extra parameter resolves an omission in the plan's abbreviated signature: a JSON schema alone does not retain the pydantic class needed for validation.

For a forced call:

1. Find exactly one `tool_use` block whose name equals the forced tool name. Do not assume `response.content[0]`.
2. Validate its `input` with `output_model.model_validate(...)` and return `validated.model_dump(mode="json")`.
3. Treat a missing, duplicate, wrong-name, non-object, or pydantic-invalid tool input as a structured-output failure.
4. Make **exactly one** repair request. Append the original assistant response content unchanged, including any `thinking` or `redacted_thinking` blocks, then append one user `tool_result` for the failed `tool_use_id` with `is_error: true` and a concise pydantic error summary. If there is no usable `tool_use_id`, append a delimited user text correction instead. 5. The repair prompt may include field paths, error types, and safe validation messages, but never `repr(input)`, the full invalid payload, original prompts, credentials, or image data.
6. Charge and aggregate usage for the first response before deciding whether to repair. If that charge exceeds the budget, raise immediately and do not spend more on repair.
7. Validate the second response once. If invalid, raise `StructuredOutputError` chained from the final validation/shape failure. Never make a third semantic request.
8. Transport retries inside either physical request do not consume the one semantic repair. Conversely, the repair is not a transport retry and must not be hidden in tenacity.

### Usage and costing

Normalize absent/`None` cache counts to zero. Reject negative usage counts as malformed SDK responses.

For configured rates per million tokens:

```text
cost_usd = (
    input_tokens * input_per_million
    + output_tokens * output_per_million
    + cache_creation_input_tokens * cache_write_5m_per_million
    + cache_read_input_tokens * cache_read_per_million
) / 1_000_000
```

Use `Decimal` internally and convert the final cost to float. Do not round before charging or aggregation. The focused hand calculation must prove that each class is charged once and that cache tokens are not also charged as uncached input.

After each physical response:

1. compute that response's usage and cost;
2. charge the shared `BudgetGuard` immediately;
3. emit safe completion telemetry;
4. aggregate it into the logical `ClaudeUsage` result when execution continues.

If `BudgetGuard.charge` raises, propagate `BudgetExceeded`. Pipeline conversion to `run.failed` belongs to the later pipeline integration step; do not edit the current pipeline here.

### Transport retry boundary

Use tenacity with **three total attempts** (initial request plus at most two retries) and random exponential jitter capped at 30 seconds.

Retry only:

- `anthropic.APIConnectionError`, including `APITimeoutError`;
- `anthropic.RateLimitError` / status 429;
- `anthropic.APIStatusError` where `status_code >= 500`, including 529 overload and 504 timeout.

Never retry:

- 400 contract/schema/model errors;
- 401 authentication or the known misleading unwhitelisted-model response;
- 403 permission, 404, or other non-429 4xx responses;
- pydantic validation (that uses the single semantic repair boundary);
- `StructuredOutputError`, `BudgetExceeded`, local validation/programming defects, or cancellation.

There is no outer catch-and-wrap around `complete`. Preserve typed SDK exceptions after retry exhaustion so callers can classify them. A failed transport attempt has no returned usage and therefore no token charge.

### Redacted structured logging

Use `structlog.get_logger(__name__)`. Emit one event per physical response and one event per transport retry/exhaustion. Safe fields are limited to:

- event name;
- resolved model;
- physical attempt number;
- latency in milliseconds;
- status code when present;
- SDK exception class name, never `str(exception)` or `repr(exception)`;
- request ID (`Message._request_id` or the typed exception's request ID) when present;
- the four token counts, total input tokens, cache-hit boolean, per-response cost, and cumulative budget spend;
- stop reason on a successful response.

Never log system blocks, messages, tool definitions, tool inputs/results, pydantic payload values, images/base64/bytes, API keys, headers, bearer values, the base URL, authenticated URLs, raw request/response bodies, or exception text. Do not bind Settings or SDK client objects into structlog context. A test must put secret sentinel strings in the API key, prompt, tool input, image bytes, base URL, and exception text and prove none appear in captured serialized events.
