## Per-File Specification

### `src/integrations/bitbucket_client.py`

Create the async read-only client. Public surface:

```python
class BitbucketClient:
    def __init__(
        self,
        config: Settings | None = None,
        client: httpx.AsyncClient | None = None,
    ) -> None: ...

    async def aclose(self) -> None: ...
    async def __aenter__(self) -> Self: ...
    async def __aexit__(self, *_args: object) -> None: ...

    async def read_file(self, path: str, at: str) -> str: ...
    async def list_files(self, path: str, at: str) -> list[str]: ...
```

#### Construction and ownership

- If `config` is `None`, import and use `src.config.settings` lazily, matching `JiraClient`.
- Read the API root and PAT from `config.bitbucket_base_url` and `config.bitbucket_pat`.
- Read project and repository slug from `config.track.repo.project` and
  `config.track.repo.slug`. Never hardcode `EGGAUTO`, `enovia-plm-test-automation`, a host, or a
  branch in runnable code.
- Build the repository root as:

  ```text
  {bitbucket_base_url}/rest/api/1.0/projects/{project}/repos/{slug}
  ```

  Strip only the trailing slash from `bitbucket_base_url`.
- Send `Authorization: Bearer <PAT>` on every request. Keep the PAT as `SecretStr` until header
  construction. Never log, persist, return, or include it in exception text.
- Use an internal `httpx.AsyncClient(timeout=60.0)` when none is injected. The 60-second value
  matches the proven integration smoke.
- Close only an internally created client. Never close an injected client.

#### Repository path handling

- `path` is a logical repository-relative path, without a leading slash.
- Remove leading/trailing `/` only for URL assembly; do not mutate interior characters.
- Percent-encode each logical path safely while preserving `/` separators. A space, `#`, `%`, `?`,
  or non-ASCII character in a file name must remain part of the repository path, not become a URL
  fragment or query string.
- `list_files("", at)` addresses the repository-root `/files` endpoint without a spurious trailing
  slash. `read_file("", at)` is not a supported public use; reject it with `ValueError` before a
  request.
- Do not join paths against the local working copy and do not add filesystem fallback logic here.
  This client is the remote fallback boundary.

#### `read_file`

- Issue exactly one logical `GET` to `{repo_root}/raw/{encoded_path}` with query
  `{"at": at}`.
- Call `raise_for_status()` and return `response.text` unchanged. Do not strip whitespace, normalize
  line endings, parse JSON, or write the content to disk.
- The method returns text because its Plan1 callers consume SenseTalk source. Binary artifact reads
  are not part of this step.

#### `list_files`

- Issue `GET {repo_root}/files/{encoded_path}` or `GET {repo_root}/files` for the root, with `at` and
  the current `start` query value.
- Start at `0`. Preserve the server's returned order and concatenate each page's `values` into one
  `list[str]`. The Bitbucket endpoint is recursive; do not recurse client-side and do not prefix the
  requested directory a second time.
- Validate every page before using it:
  - the response is a JSON object;
  - `values` is a list containing only strings;
  - `isLastPage` is a boolean;
  - if `isLastPage` is false, `nextPageStart` is an integer, is not a boolean, and advances beyond
    the current `start`.
- A malformed page raises a safe `TypeError` naming only the invalid response field. It must not
  include the PAT, authenticated URL, raw response body, or source-file content.
- If `isLastPage` is true, return the accumulated list and ignore any incidental
  `nextPageStart` value.
- Use the server-provided `nextPageStart`; never derive the next offset from `size`, `limit`, or the
  number of returned values.

#### Read retry boundary

Both public methods are reads, so use the established Jira read policy locally in this module:

- at most three attempts with `tenacity` exponential backoff
  (`multiplier=0.25`, `min=0.25`, `max=2`);
- retry `httpx.TimeoutException` and `httpx.HTTPStatusError` for HTTP 5xx;
- do not retry 4xx, JSON decoding errors, response-shape `TypeError`, or caller/path `ValueError`;
- for pagination, retry only the failing HTTP page. Do not discard, duplicate, or refetch already
  accepted pages.

Keep the retry helper private to this module. Do not refactor `JiraClient` into a shared transport
base in this step; that would enlarge the review surface without changing behavior.

#### Explicit exclusions

- No Bitbucket write method, including branch creation, file edit, pull-request creation, merge,
  webhook registration, or repository settings.
- No generic public `_request` escape hatch.
- No `bitbucket_repo_url` clone behavior; `scripts/clone_repo.ps1` owns cloning.
- No new configuration keys, dependencies, models, persistence, events, or logs.
- No silent fallback to `bitbucket_branch`; `at` is explicit on both plan-specified methods.

### `tests/test_bitbucket_client.py`

Create focused async tests using `pytest-httpx`, `SimpleNamespace`, and `SecretStr`, following
`tests/test_jira_client.py`. Inject configuration; do not import or depend on real environment
values.

Cover these behaviors as separately named tests (parameterization is fine where it stays legible):

1. **Raw read contract:** `read_file` returns the exact text including leading/trailing whitespace
   and Unicode, sends bearer auth, uses the configured project/slug, and sends `at` as a query
   parameter.
2. **Path encoding:** a repository path containing spaces plus a URL-significant character reaches
   the intended `/raw/...` path with `/` separators preserved.
3. **Empty raw path:** raises `ValueError` and sends no request.
4. **Single-page listing:** returns the ordered string values from a terminal page and addresses the
   recursive `/files/{path}` endpoint.
5. **Root listing:** an empty list path addresses `/files`, not `/files/`.
6. **Pagination:** a non-terminal page followed by a terminal page returns all values in order and
   proves the second request uses the exact server-provided `nextPageStart` while preserving `at`.
7. **Malformed values:** missing/non-list `values` and a non-string member raise safe `TypeError`.
8. **Malformed page state:** non-boolean `isLastPage`, missing/non-integer `nextPageStart`, and a
   non-advancing next start raise safe `TypeError` without another request.
9. **Timeout retry:** a read can fail twice with timeout and succeed on attempt three; exactly three
   requests occur.
10. **5xx retry on a later page:** only the failing page is retried, accepted first-page values are
    neither lost nor duplicated, and the third logical outcome succeeds.
11. **4xx boundary:** a 4xx raises `httpx.HTTPStatusError` after one request.
12. **Client ownership:** exiting the Bitbucket context does not close an injected
    `httpx.AsyncClient`; `aclose` is safe for the internally owned client.

Do not make tests assert the PAT through exception strings or print it. Inspect the outgoing
request header only in the successful mocked request.
